# OpenAI API Key 上游换号重试设置

管理员在「账号」中创建或编辑 OpenAI API Key 账号时，可以使用「上游换号重试」面板。批量编辑也支持此设置，仅在全部目标均为 OpenAI API Key 类型时显示；需先勾选「批量设置上游换号重试」，避免修改未选择的字段。

- **上游换号重试**：开启后，为该账号的出站请求添加 `X-Sub2API-Retry-Account: True`。上游需要支持这一约定，才能在输出内容前失败时调度其他账号。
- **最大换号重试次数**：填写非负整数。`2` 表示首次之外最多换号两次，`0` 表示不换号。留空不发送 `X-Sub2API-Max-Retries`，使用上游默认上限。实际次数仍受上游账号可用性和服务端上限约束。

配置按账号存入 `credentials`，无需数据库迁移：

```json
{
  "openai_upstream_retry_account": true,
  "openai_upstream_max_retries": 2
}
```

最大次数接受 `0` 至 `2147483647` 的整数；后端拒绝负数、小数、字符串和超出范围的值。使用 `null` 清空已有次数配置，适用于全量编辑和批量 JSONB 合并更新。关闭时保存 `openai_upstream_retry_account: false`，不再由此面板添加重试请求头。

专用设置独立于通用「请求头覆写」开关，开启时优先于这两个同名覆写字段，并清除大小写变体以避免重复请求头。关闭或未配置时保留原有通用覆写行为，其他请求头与账号凭据保持不变。OAuth、Setup Token 及其他平台不会应用这组专用参数。

统一出站链路覆盖 Responses、Chat Completions、Messages 兼容转发、图片、Embeddings、WebSocket 握手，以及已有使用同一构建链路的账号测试和模型探测。参数要求上游执行换号，本分支不会因此新增本地请求重放；已开始输出或已建立会话后的处理仍由上游决定。
